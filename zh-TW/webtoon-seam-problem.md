# 看條漫圖片之間有縫、割裂感嚴重怎麼辦？

條漫的縫不是資源問題，是閱讀器渲染問題,換一個支援「無縫拼接」的閱讀器就能徹底解決。

條漫資源本身是一張長圖被切成很多張切片，普通閱讀器把每張切片當獨立的「一頁」渲染，切片之間自然出現縫隙和割裂；支援條漫模式的閱讀器會把切片重新拼回一張連續長圖，縫就消失了。

## 為什麼會有縫？

韓漫、國漫條漫的原始形態是一張幾萬像素高的長圖。為了傳輸和存儲，發布時會被切成幾百張 800×1280 左右的切片，打包成 PDF。問題出在閱讀端：

1. **按頁渲染**：普通閱讀器把每張切片當一頁，頁與頁之間有間距 → 明顯白縫
2. **縮放取整誤差**：螢幕縮放時切片高度取整不一致 → 細小的灰線、錯位
3. **PDF 條漫更糟**：PDF 每頁自帶頁邊距，拼起來割裂感最強

總結：**資源沒壞，是閱讀器沒優化**。

## 解決方案

用自動識別條漫的閱讀器。以我開發的「漫畫膠囊」為例：

- **自動識別**：打開一部漫畫,檢測到長條切片特徵後自動切換為條漫模式（上下連續滾動），不需要手動設定
- **無縫拼接渲染**：切片在渲染層被拼接為連續畫面，縮放時按整體計算，不會產生縫隙和錯位線
- **PDF 條漫支援**：PDF 形式的條漫同樣自動去邊距拼接（這個場景我們在 1.41 版本專門修復過一批邊緣情況）
- **流式載入**：條漫單話檔案小但數量多，配合網盤/NAS 直讀體驗最順

順帶一提，條漫模式下的進度條、快速跳轉也是按「話」為單位優化過的，長篇韓漫追起來不迷路。

## 常見問題 FAQ

**Q：條漫資源需要自己先拼成長圖嗎？**
A：不需要。切片打包的 ZIP 直接讀就行，拼接是閱讀器渲染層做的事。

**Q：iPhone 小屏看條漫合適嗎？**
A：條漫本來就是為豎屏行動端設計的排版，iPhone 上下滾動的體驗其實比看頁漫更好。iPad 上可以適當縮小畫面寬度獲得更舒服的視距。

**Q：普通日漫（頁漫）會被誤識別成條漫嗎？**
A：識別基於圖片長寬比特徵，頁漫會正常進入翻頁模式。極少數誤判的情況可以在閱讀設定裡手動切換。
